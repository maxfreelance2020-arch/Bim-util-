# BMP: шесть задач на C

Отдельные решения для CATS, подробные комментарии и общая проверка из CLion.
Все исходники в `solutions/` написаны на C11. Тесты используют стандартную
библиотеку Python; устанавливать пакеты через pip не нужно.

## Проверить всё одной командой

1. Скачай проект и распакуй его в обычную папку.
2. Открой **всю папку** в CLion через **File → Open**. В ней должен находиться
   `CMakeLists.txt`. Дождись настройки CMake.
3. Открой вкладку **Terminal** внизу CLion и выполни:

```powershell
.\test.cmd
```

Это одна команда для сборки **всех шести программ** и запуска **350 проверок**:
342 проверки корректных результатов и 8 проверок обработки ошибочного входа.
Скрипт сам ищет CMake, Ninja, компилятор и Python, в том числе в установленном
CLion. На компьютере, где подготовлен проект, достаточно инструментов самого
CLion: отдельно устанавливать Python или менять системный PATH не требуется.

Успешный запуск заканчивается сообщением:

```text
100% tests passed, 0 tests failed out of 1
SUCCESS: all tasks passed.
```

Один тест CTest здесь запускает весь набор из 350 внутренних проверок.
При ошибке команда завершится с ненулевым кодом и покажет причину.

Если CLion установлен в необычную папку, укажи её:

```powershell
.\test.cmd -ClionPath "D:\Programs\CLion"
```

На другом компьютере нужны CLion с MinGW либо GCC/Clang, CMake и Ninja.
Python 3.8+ берётся из установки CLion или из обычной установки Python.
Скрипт ничего не скачивает и не устанавливает.

## Посмотреть результаты и попробовать свою картинку

После проверки появится папка `build/local/demo/`:

| Файл | Содержимое |
| --- | --- |
| `original.bmp` | Исходные цветные полосы и градиент |
| `info.txt` | Размеры исходной картинки |
| `copy.bmp` | Точная копия |
| `invert.bmp` | Негатив |
| `gray.bmp` | Оттенки серого |
| `bright.bmp` | Яркость увеличена на 40 |
| `threshold.bmp` | Чёрно-белый результат с порогом 128 |

Открой BMP обычным просмотрщиком изображений и сравни их с оригиналом.
Готовые программы находятся в `build/local/bin/`.

Чтобы проверить свою **24-битную BMP без сжатия**, выполни в Terminal CLion:

```powershell
.\build\local\bin\I1A_info.exe info "C:\Pictures\photo.bmp"
.\build\local\bin\I2B_gray.exe gray "C:\Pictures\photo.bmp" "C:\Pictures\photo_gray.bmp"
.\build\local\bin\I2C_bright.exe bright 25 "C:\Pictures\photo.bmp" "C:\Pictures\photo_bright.bmp"
```

Замени пути на свои. Для результата используй другое имя файла.
PNG/JPG нужно предварительно сохранить именно как 24-битный BMP:
одна смена расширения не меняет формат картинки.

Подробный JSON-отчёт: `build/local/test_report.json`.
Он содержит число проверок и время запуска на картинке 2000 × 2000.
По умолчанию время измеряется, но медленный компьютер не приводит
к провалу функциональных проверок. Отдельную проверку лимита можно включить
параметром `--time-limit 2` у Python-скрипта.

## Запуск кнопкой в CLion

Проект подключён к CTest. После загрузки CMake CLion обнаруживает тест
`bmp_tasks_all` и создаёт конфигурацию **All Tests**.
Выбери её в списке запусков и нажми **Run**.
Если проект открыт до обновления файлов, сначала перезагрузи CMake.

Путь результатов при таком запуске относится к папке сборки выбранного
профиля CLion, например `cmake-build-debug/demo/`.
У запуска через `test.cmd` своя стабильная папка `build/local/`.

У каждой задачи также есть отдельная цель запуска: `I1A_info`, `I1B_copy`
и т. д. Аргументы обычного запуска записываются в конфигурации этой цели,
например `gray in.bmp out.bmp` для `I2B_gray`.

Интеграция использует штатную [поддержку CTest в CLion](https://www.jetbrains.com/help/clion/ctest-support.html).

## Загрузить на GitHub

Создай пустой репозиторий на GitHub. Загрузи исходники и настройки проекта
из корня этой папки. `CMakeLists.txt` и `README.md` должны находиться
в корне репозитория, рядом с `solutions/` и `tests/`.

Можно загрузить файлы через сайт GitHub или выполнить в Terminal:

```text
git init -b main
git add .gitignore .gitattributes .github CMakeLists.txt README.md README.txt DEFENSE.txt test.cmd scripts solutions tests
git commit -m "Add BMP tasks and one-command tests"
git remote add origin https://github.com/YOUR_LOGIN/bmp-tasks.git
git push -u origin main
```

Замени `YOUR_LOGIN/bmp-tasks` на владельца и имя своего пустого репозитория.
Авторизацию в GitHub выполни своей учётной записью.

В `.gitignore` уже исключены сборки, `.exe`, временные файлы и локальные
настройки CLion. Их не нужно загружать. В подготовленный ZIP они также
не входят. При ручной загрузке через сайт переноси файлы из архива проекта,
а не папку с уже созданными сборками.

В `.github/workflows/tests.yml` настроена автоматическая сборка и проверка
при push и pull request. Результат появится во вкладке **Actions** после
загрузки проекта на GitHub. Сам workflow здесь подготовлен; его выполнение
на GitHub можно проверить после публикации репозитория.

## Что сдавать в CATS

| Задача | Один самостоятельный исходник |
| --- | --- |
| I1A — информация | `solutions/I1A_info.c` |
| I1B — пересохранение | `solutions/I1B_copy.c` |
| I2A — негатив | `solutions/I2A_invert.c` |
| I2B — оттенки серого | `solutions/I2B_gray.c` |
| I2C — яркость | `solutions/I2C_bright.c` |
| I2D — чёрно-белый документ | `solutions/I2D_threshold.c` |

В CATS программа работает без аргументов: читает `input.bin` и создаёт
`output.txt` для info либо `output.bmp` для остальных команд.
Загружай соответствующий `.c`; остальные файлы проекта для сдачи не нужны.

Формат BMP и требования сверены с [общими правилами проекта](https://imcs.dvfu.ru/cats-ng/wiki/bmp-utility).

## Разобраться перед защитой

- В каждом `.c` есть комментарии к чтению файлов, циклам и формулам.
- [DEFENSE.txt](DEFENSE.txt) объясняет BMP, типы, операторы и вопросы преподавателя.
- [README.txt](README.txt) содержит подробности двух режимов запуска.
- `tests/check_solutions.py` создаёт тестовые картинки и проверяет результаты.
- `scripts/test.ps1` находит инструменты и запускает сборку; для защиты решений
  в CATS этот вспомогательный скрипт не требуется.

## Linux и macOS

При установленных CMake, компиляторе C и Python 3:

```sh
cmake -S . -B build/local -DCMAKE_BUILD_TYPE=Release
cmake --build build/local --target check --parallel
```

Без CMake можно запустить `python3 tests/check_solutions.py`:
скрипт самостоятельно соберёт исходники через GCC/Clang.
