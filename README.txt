ШЕСТЬ ЗАДАЧ НА C: BMP-УТИЛИТА
============================

БЫСТРЫЙ ЗАПУСК И GITHUB
----------------------

Откройте всю папку проекта в CLion, затем во вкладке Terminal выполните:
    .\test.cmd

Одна команда собирает шесть программ, запускает 350 проверок и создаёт
примеры результатов в build/local/demo. Готовые .exe: build/local/bin.
Полная новая инструкция для CLion и GitHub находится в README.md.
В CLion также доступна конфигурация CTest All Tests.

Сначала откройте файл своей задачи в папке solutions.
Каждый файл самостоятельный: дополнительных .h и .c для сдачи не нужно.
Код содержит подробные комментарии на русском.
В DEFENSE.txt объяснены устройство BMP, конструкции C и вопросы для защиты.

ЧТО ОТПРАВЛЯТЬ В CATS
--------------------

Задача     Файл                         Результат
I1A        solutions/I1A_info.c          output.txt
I1B        solutions/I1B_copy.c          output.bmp
I2A        solutions/I2A_invert.c        output.bmp
I2B        solutions/I2B_gray.c          output.bmp
I2C        solutions/I2C_bright.c        output.bmp
I2D        solutions/I2D_threshold.c     output.bmp

1. Откройте в CATS соответствующую задачу.
2. Выберите компилятор языка C с поддержкой C11, например GNU C.
3. Прикрепите один соответствующий файл .c из таблицы.
4. Отправьте его на проверку и посмотрите вердикт.

Программа запускается в CATS без аргументов.
Проверяющая система сама создаёт input.bin; программа сама создаёт результат.
Файлы input.bin, output.bmp, output.txt, исполняемые .exe и Python-тесты
в качестве решения загружать не нужно.

Все шесть исходников — отдельные программы с собственным main.
Для каждой задачи компилируют свой файл. Вместе в одну программу их не линкуют.
Каждый исходник поддерживает свою команду, указанную в его названии.

РЕЖИМ 1: ЗАПУСК КАК В CATS
-------------------------

В input.bin лежит:
    строка команды + один байт LF (10) + все байты BMP

Команды:
    info
    copy
    invert
    gray
    bright 10
    threshold 128

Сначала скомпилируйте нужный исходник. Например, для оттенков серого:
    gcc -std=c11 -O2 -Wall -Wextra solutions/I2B_gray.c -o imgtool.exe

Положите input.bin в текущую рабочую папку и запустите в PowerShell:
    .\imgtool.exe

Результат появится в той же рабочей папке.
I1A создаёт output.txt; остальные задачи создают output.bmp.
В output.txt находятся только два числа, например: 305 183.

input.bin — двоичный файл: не собирайте его копированием картинки в текстовый
редактор. Для обычной ручной проверки удобнее режим с аргументами ниже.

РЕЖИМ 2: ОБЫЧНЫЙ BMP И АРГУМЕНТЫ
-------------------------------

Один раз скомпилируйте нужную задачу, затем запустите её команду.
Примеры ниже предполагают, что соответствующий исходник собран в imgtool.exe:

    .\imgtool.exe info in.bmp
    .\imgtool.exe copy in.bmp out.bmp
    .\imgtool.exe invert in.bmp out.bmp
    .\imgtool.exe gray in.bmp out.bmp
    .\imgtool.exe bright 10 in.bmp out.bmp
    .\imgtool.exe threshold 128 in.bmp out.bmp

Для info размеры появляются в терминале. Для остальных команд создаётся BMP.
В этом режиме у исходного in.bmp нет строки команды перед заголовком.
Для исходного файла и результата выбирайте разные пути.
Если в имени файла есть пробелы, заключите путь в двойные кавычки.

Если команда gcc не найдена, воспользуйтесь CLion или полным путём к gcc.
На компьютере, где подготовлены решения, найден компилятор:
    C:\Program Files\JetBrains\CLion 2026.2.3.1\bin\mingw\bin\gcc.exe

Пример PowerShell с этим компилятором:
    & "C:\Program Files\JetBrains\CLion 2026.2.3.1\bin\mingw\bin\gcc.exe" -std=c11 -O2 -Wall -Wextra solutions/I2B_gray.c -o imgtool.exe

В Linux/macOS имя исполняемого файла можно задать как imgtool без .exe,
а запускать его через ./imgtool.

КАК ОТКРЫТЬ В CLION
------------------

Откройте папку проекта, содержащую CMakeLists.txt.
В списке целей запуска выберите I1A_info, I1B_copy и т. д.
Аргументы команды укажите в параметрах запуска, например:
    gray полный_путь_к_исходному.bmp полный_путь_к_результату.bmp

При запуске без аргументов input.bin должен находиться в рабочей папке,
указанной в конфигурации запуска CLion. Это может быть папка сборки,
а не папка с исходниками. Результаты создаются в этой же рабочей папке.

ЧТО УЧТЕНО В РЕШЕНИЯХ
---------------------

- 24-битный BMP без сжатия, размеры от 1 до 2000.
- Положительная и отрицательная высота в заголовке.
- Порядок байтов цветов B, G, R.
- Выравнивание каждой строки до количества байтов, кратного четырём.
- Расположение пикселей по полю bfOffBits, а не всегда с байта 54.
- Расширенные заголовки BMP: дополнительные данные сохраняются.
- copy сохраняет исходный BMP полностью, байт в байт.
- Цветовые команды меняют только байты цветов.
- Ошибки открытия, чтения и записи приводят к коду завершения 1.
- Успешное завершение имеет код 0.

ЛОКАЛЬНАЯ ПРОВЕРКА
-----------------

Тесты находятся в tests/check_solutions.py. Это вспомогательный файл,
написанный на Python, сами решения написаны только на C.

Если Python и GCC доступны:
    python tests/check_solutions.py

Можно явно указать компилятор:
    python tests/check_solutions.py --compiler "полный путь к gcc.exe"

Скрипт компилирует все исходники с -std=c11 -O2 -Wall -Wextra -Wpedantic
-Werror: предупреждения считаются ошибками. Он создаёт тестовые BMP,
запускает обе версии интерфейса и проверяет фактические результаты.

При подготовке пройдено:
    342 проверки на корректных входных данных;
    8 проверок обработки ошибочного входа;
    компиляция всех 6 программ без предупреждений.

Проверены картинки 1x1 с обоими знаками высоты, ширины 1..9,
разные высоты и размер 305x183.
Максимальная картинка 2000x2000 проверена для каждой из шести команд.
Есть тесты отрицательной высоты, V4/V5-заголовков, смещений,
ненулевого выравнивания, двоичных байтов 0/10/13/26/255, порогов 0 и 255,
изменения яркости -255 и 255, повторного негатива и bright 0.
Полный отчёт при прямом запуске Python: build/test_report.json.
При запуске .\test.cmd: build/local/test_report.json.

Локальные тесты выполнены. Отправка в CATS из этого проекта не выполнялась;
окончательный вердикт выдаст CATS после загрузки исходника.
